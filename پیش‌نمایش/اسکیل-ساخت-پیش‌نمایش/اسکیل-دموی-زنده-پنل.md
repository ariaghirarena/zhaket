# اسکیل «دموی زندهٔ پنل» — روش واقعی، نه بازطراحی

منبع: `Google Drive → AI-Brain/02-Skills/real-plugin-demo/SKILL.md` (۲۰٬۹۲۷ بایت)
نویسندهٔ اسکیل در سند خودش تصریح می‌کند: *«افزونه داخل وردپرس نصب نشد؛ آنچه ساخته شد دموی استاتیک از
دارایی‌های واقعی پنل است — CSS/JS خود افزونه، با پاسخ‌های شبیه‌سازی‌شده در همان مرورگر.»*

---

## ۰. خط قرمز

| درست | غلط |
|---|---|
| CSS و JS **دست‌نخوردهٔ** افزونه بارگذاری می‌شوند | رابط دستی بازطراحی می‌شود |
| `fetch` قبل از بوت UI رهگیری می‌شود | UI به شبکهٔ واقعی می‌رود و خطا می‌دهد |
| دادهٔ نمونه با **همان schema** پاسخ‌های PHP | دادهٔ «شبیه» که صفحه را می‌شکند |
| نوار «دادهٔ نمونه — دمو» همیشه دیده می‌شود | القای «نسخهٔ نصب‌شده روی فروشگاه واقعی» |

> دمو = **رابط واقعی + دادهٔ نمونه**. نه «تصویر ساختگی»، نه «نصب واقعی».

## ۱. الگوی الف — SPA + REST (بچرخون از این نوع است)

```
assets/admin/app.css          ← استایل واقعی (۱۱۷ KB)
assets/front/wheel.css        ← استایل گردونهٔ واقعی (۵۱ KB)
assets/admin/wheel.js  …      ← ترتیب وابستگی‌ها
assets/admin/ui.js            ← BC.api → fetch(root + path)
assets/admin/charts.js
assets/admin/fields.js
assets/admin/editor.js
assets/admin/pages.js
assets/admin/app.js           ← پوسته، روتر hash، boot
```

ترتیب بارگذاری **مقدس** است:

1. `BCH` config (root, nonce, routes, fa, theme, pluginUrl, woo, canManage)
2. `BECHARKHOON` (config گردونهٔ فرانت)
3. `mock-api.js` + `mock-routes-*.js`  ← **قبل از همهٔ فایل‌های UI**
4. `wheel.js → ui.js → charts.js → fields.js → editor.js → pages.js → app.js`

اگر mock بعد از `app.js` بیاید، درخواست `bootstrap` زودتر به شبکه می‌رود و shell با خطا می‌ماند.

## ۲. الگوی ب — PHP View + jQuery AJAX

برای افزونه‌هایی مثل `ARIAGH.AIWRITER`: قالب‌های `admin/views/*.php` را با یک شیم `php-cli`
(`get_option`, `wpdb`, `esc_*`, `admin_url`, …) در **زمان ساخت** رندر کن، خروجی همهٔ تب‌ها را در
`views-bundle.js` بریز، `?tab=` را به `#hash` نگاشت کن، و `$.post('__demo_ajax__')` را قبل از
`admin.js` رهگیری کن. (برای بچرخون لازم نیست: پنل SPA است.)

## ۳. قرارداد پاسخ‌ها برای بچرخون (استخراج‌شده از `Rest.php` + `Stats.php` + `Settings.php`)

- `GET /bootstrap` → settings, themes[], templates[], sms{}, sms_events, sms_mode, conditions{}, triggers, rule_defaults, roles[], payments[], shipping[], statuses[], integrations, defaults, slice_defaults, field_defaults, prize_types[], currency, site, wheels[], shortcodes[]
- `GET /dashboard?from&to&wheel` → from, to, totals{14 metric + conversion, win_rate, redeem_rate, open_rate}, previous, series{day→metrics}, prizes[], sources[], hours[24], credits, recent[12], wheels[], checks[]
- `GET /wheels` → [] با {id,title,status,priority,ab_group,theme,mode,display,slices,preview,spins,wins,redeemed,revenue,updated,open}
- `GET /spins|/leads|/credits|/people|/sms/log|/logs` → `{items:[], total:n}` (+`sum` برای people)
- `GET /rules` → `{rules:[]}` · `GET /settings` → شیء تنظیمات با رازهای ماسک‌شده
- `GET /reports` → build شده · `/reports/orders` → `{items,total}`
- `GET /bulk/campaigns` → `{items,total}`

**قاعدهٔ طلایی:** برای GET ناشناس، پاسخ **خالیِ نوع‌درست** بده (`[]` یا `{items:[],total:0}`)،
نه دادهٔ خیالی. برای POST/PUT/DELETE ناشناس یا حساس، موفقیت جعلی نده؛ پیام
«در دموی مرورگری غیرفعال است» با کد ۴۰۳ برگردان.

## ۴. QA که واقعاً انجام می‌شود

- Console و Network: صفر خطای JS، صفر ۴۰۴، صفر درخواست بیرونی.
- همهٔ routeها یکی‌یکی باز شوند (`#/dashboard … #/guide` و `#/edit?id=1`).
- دسکتاپ ۱۴۴۰ و موبایل ۳۹۰.
- اسکرین‌شات فقط از Chromium واقعی؛ jsdom برای layout/فونت کافی نیست.
- بعد از آخرین تغییر CSS، اسکرین‌شات‌ها **دوباره** گرفته شوند.
